## 数学定义

对每次 forward 中 A 刚计算出的 `h_A`，执行：

```text
z[i] ~ Normal(0, 1)
uploaded[i] = cast_to_model_dtype(float32(h_A[i]) + sigma * z[i])
```

噪声按每个张量元素采样。`sigma` 与 h_A 的数值具有相同单位，是绝对标准差。
这里没有按 token RMS 自适应缩放、归一化、裁剪、量化压缩或事后去噪。
普通高斯分布在未舍入时的理论平均绝对值为 `sigma * sqrt(2/pi)`，
实际传输数值会受 FP16/BF16 舍入影响，报告使用实际差值而不是理论值冒充实测。

`sigma=0` 是直接返回原张量的特殊分支，不生成随机数，不做 FP32 往返转换。
NaN、Inf、负 sigma、非法种子、异常输入形状和非有限加噪输出都会被拒绝。
加噪失败时不会上传本次 forward，已创建的会话按原有异常策略清理。

## 接入接口

`NOISE_POLICIES` 注册分布策略；目前只注册 `gaussian`。
新策略应实现构造、`apply(hidden)`、`describe()`，独立保存随机状态，
保持形状、设备、dtype 和有限数值，不原地修改输入，并补充零扰动及异常回归。
这与 Qwen2/Qwen3-MoE 的模型适配器、p/q 切分接口相互独立。

`NoiseSession.reset()` 先取得新的 `RemoteCache`，再给**这个缓存**的 RPC 包一层 `NoisyRpc`。
`NoisyRpc` 只修改 `/v1/forward` 的 `hidden` 字段。
mask、位置、序号、会话创建/关闭均复用原 HTTPS 协议；种子、原文和未加噪激活不会额外上传。
共享模型的 RPC 和权重不被替换，因此不同会话/不同条件不会改写彼此的噪声策略。
返回的 B 输出不再加噪。

## 缓存、随机数与复现

一轮回答内，各段 KV 缓存正常增长；prefill 上传完整新输入，decode 通常只上传一个新 token。
旧的 B/C 缓存已经包含此前扰动的影响，不能更换 sigma/seed 后继续把它当成干净缓存。
本阶段选择每个试验/每轮聊天重新计算文字历史，不做跨轮缓存复用。
这样不需要定义“编辑噪声前缀后如何恢复随机流”的额外策略，也不会悄悄混用试验条件。

使用 CPU 私有 `torch.Generator` 生成 FP32 正态样本。
实际种子由 SHA-256 对固定版本标记、基础种子、问题 ID 派生，取 `[0, 2**63)` 内的整数。
不能使用会随 Python 进程变化的 `hash()` 作为试验种子。
同一问题/基础种子在不同强度下使用相同起始随机流，便于配对比较；
输出长度分叉后，不把后续采样位置说成相同语义位置。

复现需要相同代码、权重、分词模板、问题 ID/文本、基础种子、设备/精度、依赖和切分。
固定种子不等于密码学安全，公开种子与模型知识可能削弱隐藏效果。
结果中的种子和 token 属于本地敏感实验数据，不应公开上传。

## 评测设计

默认是 6 个固定问题、4 个 sigma、2 个基础种子，共 48 个独立 HTTPS 试验。
5 个短题提供参考答案，1 个开放题仅保留回答供人工查看。
这一小集合只验证程序行为，不代表真实业务、中文能力或论文基准性能。
可以修改 `prompts.json` 或 `evaluation.prompts_file` 扩展案例。
每题写 `prompt` 或交替的 `messages`，可选 `answers` 列出允许的严格答案。

完整模型使用当前本地权重、普通 KV Cache、相同输入及贪心生成。
每个问题单独生成完整参考回答，不依赖任何第一阶段旧文件。
每题先执行所有种子的零噪声试验，再执行非零条件；即使配置网格把 0 写在最后也如此。
预热分别执行完整模型和无噪声 HTTPS，不计入 trial 行或通信平均值。

零噪声关卡要求生成 token、回答文字和每步 logits 通过比较，默认 `atol=rtol=1e-5`，
同时记录是否完全相等。关卡没跑完是 `null`，失败是 `false`，覆盖全部试验后才写 `true`。
非零噪声不要求与完整模型一致，否则会把要测量的影响错误地当成程序缺陷。

## 指标区分

| 指标 | 定义与限制 |
|---|---|
| 任务得分 `task_score` | 有标准答案才计分；NFKC、大小写折叠、空白规范化后严格匹配；不去标点、不做子串/语义匹配 |
| `task_accuracy` | 本 sigma 所有带答案 case/seed 试验的平均得分；不是置信区间 |
| `reference_task_accuracy` | 相同题目的完整模型严格答案得分，帮助发现本来就不会的题 |
| `accuracy_drop_vs_reference` | 完整模型得分减加噪得分，可为负，不强行裁剪为 0 |
| `reference_exact_match_rate` | 生成 token 序列与完整模型相等的比例，包含 EOS；只是输出稳定性 |
| 前缀比例 | 首次生成 token 分歧前的共同长度，除以两个生成序列中较长者的长度 |
| 首 token logits RMSE / 最大误差 | 两边输入提示词一致时的原始分数变化，不对分叉后不同文本的 logits 强行求误差 |
| 实际噪声 RMS/平均绝对值 | 从上传 dtype 数值减原始 h_A 后统计，不保存整份激活 |
| `nonempty_rate` | 回答非空率，不代表语义正确 |

只有同一提示上下文的首步分数直接可比。后续 token 已改变时，分数还混入了不同上下文的影响。
本阶段没有 teacher-forcing 困惑度、ROUGE/BLEU 语义评价或攻击成功率；
不要用 `reference_exact_match_rate` 替代这些指标。

## 资源测量

生成时间使用 CUDA 同步边界，不包含模型加载与分词；
包含本轮生成中的 TLS 往返、噪声采样/搬运/统计和 logits 采集。
`trial_wall_seconds_including_snapshot_and_close` 还包括结果搬回 CPU、解码和关闭会话。
试验顺序固定，没有做系统性的随机顺序吞吐基准，不能据此声称加噪加速或论文级性能。

通信使用该客户端 RPC 计数器的前后差，覆盖新会话、所有 forward 和最终 close。
不包含预热、健康检查和其他 trial，也不包含 HTTP/TLS/TCP 头部开销。
噪声不改变张量形状；生成长度变化可能改变通信总量，所以报告同时保留 token 数与调用数。

显存只记录客户端进程 PyTorch 的峰值已分配量，CPU 为 `null`；
评测中它包含额外完整参考模型，不是纯 A/C 部署显存。
服务端只报告所属权重的字节，没有测量其缓存/激活/运行时总峰值，也不把两者相加冒充总显存。

## 安全与范围

HTTPS 负责传输保密和本地服务认证；服务器解密后仍然看到带噪隐藏向量、mask、位置和长度。
噪声实验没有隐私邻接关系、敏感度上界、裁剪、epsilon/delta 预算与自回归重复发布核算，
因此不提供差分隐私结论。固定种子和多次重复同一输入也不能当成安全部署策略。
模型反演攻击、重建文本评测及真实威胁模型需要单独设计。
这里完成的是五阶段推理原型，未宣称完成整篇论文或生产环境部署。
